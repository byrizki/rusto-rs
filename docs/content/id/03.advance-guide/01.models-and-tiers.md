RustO! memisahkan mesin runtime inti dari berkas bobot model agar biner rilis aplikasi Anda tetap ramping (di bawah 10 MB) dan bebas dari ketergantungan paket bawaan yang membengkak.

Jika Anda baru pertama kali mencoba dan bingung memilih model: **langsung gunakan `indraocr` (bawaan)**. Berukuran ~5.5 MB (detektor 396 KB + rekognisi 4.9 MB), model ini mencatat latensi super cepat **439.2 ms** (rata-rata dokumen penuh pada benchmark OmniDocBench) serta akurasi tinggi untuk membaca KTP, SIM, struk lokal, formulir pajak, maupun dokumen teks Latin standar. Jika memiliki batasan memori atau penyimpanan ketat pada perangkat edge/mobile, pilih **`ppocrv6-tiny-int8`** (~3.4 MB) atau **`ppocrv6-tiny`** (~6.1 MB).

## 1. Model Dasar OCR Kanonikal

RustO! menyediakan model dasar kanonikal resmi yang dapat langsung ditentukan melalui nama (misalnya `model = "indraocr"` atau `model = "ppocrv6-tiny"`). Model dasar menggabungkan deteksi, rekognisi, dan kamus:

| Model Kanonikal           | Target Lingkungan / Kasus Penggunaan                         | Ukuran Dasar | Latensi Rata-Rata OmniDocBench | Keunggulan Utama                                                                                                                     |
| :------------------------ | :----------------------------------------------------------- | :----------: | :----------------------------: | :----------------------------------------------------------------------------------------------------------------------------------- |
| **`indraocr`** _(Bawaan)_ | Dokumen Indonesia: KTP, SIM, struk lokal, formulir, Latin    | **~5.5 MB**  |  **439.2 ms** (dokumen penuh)  | Model unggulan bawaan dari DataLab (`datalab-to/indra-ocr`). Kecepatan tinggi, akurasi kosakata, dan pengenalan tata letak regional. |
| **`ppocrv6-tiny`**        | Aplikasi mobile (iOS, Android, React Native, Flutter) & CLI  | **~6.1 MB**  |   1,104.4 ms (dokumen penuh)   | Titik temu terbaik antara kecepatan, akurasi, dan ukuran unduhan ringan.                                                             |
| **`ppocrv6-tiny-int8`**   | Perangkat edge, IoT, dan mobile dengan sumber daya terbatas  | **~3.4 MB**  |       INT8 mobile cepat        | Bobot terkuantisasi 8-bit untuk efisiensi memori maksimal dengan degradasi akurasi sangat minim.                                     |
| **`ppocrv6-small`**       | Aplikasi desktop, microservice backend, dokumen padat        | **~30.5 MB** |   3,700.4 ms (dokumen penuh)   | Arsitektur lebih dalam untuk teks kecil, tabel padat, dan noise pindaian.                                                            |
| **`ppocrv6-small-int8`**  | Layanan backend berthroughput tinggi dan server microservice | **~16.7 MB** |      INT8 server seimbang      | Model small terkuantisasi 8-bit yang menghadirkan akurasi setara desktop dengan ukuran separuh lebih hemat.                          |
| **`ppocrv6-medium-int8`** | Kluster pemrosesan dokumen batch presisi maksimal            |  **~77 MB**  |      INT8 presisi tinggi       | Recall karakter maksimal untuk dokumen pindaian bergradasi buruk dan formulir kompleks.                                              |
| **`ppocrv5-mobile`**      | Baseline multibahasa mobile (Latin, Sirilik, Arab, Korea)    |  **~21 MB**  |   Paket multibahasa baseline   | Baseline multibahasa teruji dengan dukungan orientasi baris 180° terintegrasi.                                                       |
| **`ppocrv4-mobile`**      | Bahasa Jepang (Kanji/Kana) & Tionghoa Tradisional (CHT)      |  **~21 MB**  |       Paket CJK baseline       | Cakupan kamus aksara CJK lengkap serta kompatibilitas regional Kannada.                                                              |

> [!NOTE]
> Paket bahasa multibahasa dan tahap pemahaman dokumen tambahan **tidak** digabungkan ke dalam paket pipeline dasar. Seluruhnya didistribusikan sebagai aset mandiri yang modular.

## 2. Arsitektur Pipeline Modular

RustO! memisahkan secara tegas antara **Pipeline Dasar OCR** dan **Tahap Tambahan Opsional**:

```mermaid
flowchart TD
    subgraph BASE["Pipeline Dasar OCR (Inti Modular)"]
        DET["Deteksi Teks<br/>(det.rten)"] --> REC["Pengenalan Teks<br/>(rec.rten + dict.txt)"]
    end

    subgraph EXTRAS["Tahap Opsional Mandiri (Aset Terpisah)"]
        UNWARP["1. Unwarp Dokumen<br/>(uvdoc.rten)"]
        ORIENT["2. Orientasi Halaman<br/>(indra_orient.rten / ppocr_orient.rten)"]
        LAYOUT["3. Analisis Tata Letak<br/>(layout_cdla.rten / layout_publaynet.rten)"]
        CLS["4. Klasifikasi Sudut Baris<br/>(ppocr_cls.rten)"]
        ORDER["5. Pemulihan Urutan Baca<br/>(indra_order.rten)"]
    end

    UNWARP -.-> BASE
    ORIENT -.-> BASE
    LAYOUT -.-> BASE
    BASE -.-> CLS
    BASE -.-> ORDER
```

### Karakteristik Aset Model:

- **Bobot dasar terpisah**: Pipeline dasar (`det.rten` + `rec.rten` + `dict.txt`) dan tahap opsional (`cls`, `orient`, `unwarp`, `layout`, `reading-order`) disediakan sebagai berkas `.rten` mandiri yang dapat dipasang secara dinamis.
- **Model Tata Letak PP-Structure v3 & Indra Layout / Reading Order**:
  - **`layout_cdla.rten`** (5.8 MB): Segmentasi 10 kelas tata letak dokumen (Teks, Judul, Gambar, Keterangan Gambar, Tabel, Keterangan Tabel, Header, Footer, Referensi, Persamaan).
  - **`layout_publaynet.rten`** (5.2 MB): Segmentasi 5 kelas tata letak dokumen (Teks, Judul, Daftar, Tabel, Gambar).
  - **`indra_order.rten`** (2.9 MB): Model urutan baca dan tata letak dari DataLab Indra OCR (pengganti standar untuk `order.rten` lawas). Berfungsi menyusun baris teks multi-kolom ke urutan baca alami manusia.
- **Pemulihan Urutan Baca Cerdas (Neural Reading Order)**: Menggunakan transformer pemulihan urutan baca yang diaktifkan melalui opsi `--reading-order` atau `enableReadingOrder`.

## 3. Alur Resolusi Model

RustO! menerapkan alur pencarian deterministik 3 tingkat pada seluruh bahasa pemrograman dan CLI:

```mermaid
flowchart LR
    A["1. Lokasi Spesifik Pengguna<br/>(--model-path / modelPath / overrides)"] -->|Ditemukan| RUN["Jalankan Inferensi"]
    A -->|Tidak Ditemukan| B["2. Direktori Cache Lokal<br/>(~/.cache/rusto/models)"]
    B -->|Ditemukan| RUN
    B -->|Tidak Ditemukan| C["3. Unduh Otomatis<br/>(Aset .rten GitHub Release)"]
    C -->|Unduh & Simpan ke Cache| RUN
```

1. **Jalur Spesifik Pengguna**: Jika jalur folder model (`--model-path` / `modelPath`) atau override komponen spesifik (`--det-model`, `--rec-model`, `--dict`) diberikan, RustO! akan memeriksa lokasi tersebut terlebih dahulu.
2. **Direktori Cache Lokal**: Jika tidak ditemukan di lokasi pengguna, RustO! mencari di folder cache (`~/.cache/rusto/models` atau `--cache-dir`).
3. **Unduh Otomatis**: Jika berkas belum ada di cache, RustO! secara otomatis mengunduh berkas `.rten` dan `.txt` dari GitHub Releases resmi (`rusto-rs/models-rten`) ke direktori cache.

## 4. Mengunduh Model

### Menggunakan CLI (`rusto download`)

Unduh model sebelum menjalankan aplikasi untuk skenario offline atau kontainer:

```bash
# Unduh model default (indraocr) ke direktori cache
rusto download

# Unduh model kanonikal tertentu
rusto download --model ppocrv6-tiny
rusto download --model ppocrv6-small

# Unduh paket bahasa regional
rusto download --model ppocrv5 --lang latin
rusto download --model ppocrv4 --lang japan

# Unduh seluruh model kanonikal sekaligus
rusto download --all

# Menggunakan direktori cache kustom
rusto download --model indraocr --cache-dir /opt/models/cache
```

### Unduhan Terprogram di Berbagai Bahasa Pemrograman

```typescript
// TypeScript / Node.js
import { RustO } from '@rustors/node';

const paths = RustO.downloadModel('indraocr', 'latin');
const allPaths = RustO.downloadAllModels();
```

```python
# Python
from rusto import RustO, download_model, download_all_models

paths = download_model(model="indraocr", lang="latin")
all_paths = download_all_models()
```

```csharp
// C# (.NET)
using RustODotnet;

string[] paths = RustO.DownloadModel("indraocr", "latin");
string[] allPaths = RustO.DownloadAllModels();
```

## 6. Verifikasi Checksum

Setiap rilis menyertakan berkas `SHA256SUMS`. Anda dapat memverifikasi integritas unduhan dengan:

```bash
sha256sum -c SHA256SUMS --ignore-missing
```
