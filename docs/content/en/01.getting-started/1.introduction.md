**RustO!** is a high-performance Optical Character Recognition (OCR) engine and cross-platform toolkit written in pure Rust. Powered by [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) (`ppocrv6-tiny` FP32 by default, Apache 2.0) and optional [DataLab Indra OCR](https://github.com/datalab-to/indra-ocr) models running on RustO's pure-Rust MNN neural inference runtime (`rusto-nn`) and [RTen](https://github.com/robertknight/rten) (`.rten`), RustO! delivers sub-second inference speeds, ultra-low memory overhead, zero OpenCV or C++ runtime dependencies, and **100% character-level transcription parity** on standard document test sets.

## 🎯 Architecture Pipeline

RustO! orchestrates a 6-phase end-to-end OCR, geometric unwarping, and layout analysis pipeline optimized for edge devices, browsers, mobile apps, and high-throughput servers:

```mermaid
flowchart TD
    A["Input Image Source<br/>(Path, Encoded Bytes, Native URI, or Decoded RGB)"] --> B["1. Pre-Detection<br/>(Optional Whole-Page Orientation & UVDoc 3D Unwarping)"]
    B --> C["2. Layout & Text Detection<br/>(Optional PicoDet Layout + DBNet / LineNet Heatmap)"]
    C --> D["3. Post-Detection<br/>(Binarization, Dilation, Polygon Unclipping & Filtering)"]
    D --> E["4. Pre-Recognition<br/>(Optional 180° Line CLS, Crop & Graph Reading Order)"]
    E --> F["5. Batched Text Recognition<br/>(LineNet / SVTR / CRNN Decoding)"]
    F --> G{"6. Output Granularity"}
    G -->|"as_lines / as_words"| H["Structured Output<br/>(TextResult with BoxPoints, Frame, RegionId & LayoutType)"]
    G -->|"as_spatial"| I["Spatial Layout Reconstruction<br/>(Preserved Tables, Receipts & Multi-Column Text)"]
```

## ⚡ Key Highlights & Advantages

- **🚀 100% Pure Rust Core**: Zero OpenCV or C++ runtime dependency. Binarization, contour tracing, polygon clipping, 3D grid unwarping, and affine transformations are implemented in memory-safe Rust with SIMD acceleration.
- **📦 Default PP-OCRv6 Tiny FP32 (~5.9 MB)**: Defaults to permissive Apache 2.0 **PP-OCRv6 Tiny** (`ppocrv6-tiny`) achieving **46.53%** baseline OmniDocBench accuracy (**62.72%** with pure-Rust heuristic reading order, **57.91%** with CDLA full pipeline) on pure-Rust MNN (`rusto-nn`), with decoupled model weights and zero-config automatic caching on first run.
- **📄 End-to-End Document Understanding**: Built-in UVDoc 3D geometric unwarping, 4-way page orientation correction, PicoDet 10-class CDLA / 5-class PubLayNet layout detection (`region_id` & `layout_type`), neural reading order (`indra_order.rten`), and 2D spatial text reconstruction.
- **🧠 Broad Model Ecosystem**: First-class support for **Indra OCR** (`indraocr`), **PP-OCRv6** (Tiny, Small, Medium), **PP-OCRv5** (Mobile, Server), and **PP-OCRv4** (Mobile, Server) in FP32, FP16 (`ppocrv6-tiny-fp16`), and INT8 precision.
- **🌐 Multilingual Coverage**: Indra OCR covers Latin, RTL (`ar`), and World scripts, while PP-OCRv6 unifies 50+ languages in a single dictionary alongside dedicated CJK, Cyrillic, Arabic, Korean, Japanese, and Devanagari models.
- **📱 12 Cross-Platform SDKs + C FFI & CLI**: Unified fluent builder API (`as_lines` / `asLines` / `AsLines` + `.run()` / `.Run()`) across **Rust**, **Node.js**, **Python**, **Golang**, **Java**, **Dart**, **Flutter**, **Web (WASM)**, **React**, **React Native**, **iOS (Swift)**, **Android (Kotlin)**, **.NET / C#**, **C FFI**, and the **`rusto` CLI**.

## 📊 Performance & Parity Comparison

Empirically evaluated against official PaddleOCR and RapidOCR (C++ ONNX Runtime) using the standard **OmniDocBench** dataset and standard document scans (1600×993 px, 27 text lines):

| Metric                                       | RustO! (Pure Rust MNN / RTen)                                                                 | Traditional OpenCV + C++ Pipeline                      | Advantage                          |
| :------------------------------------------- | :-------------------------------------------------------------------------------------------- | :----------------------------------------------------- | :--------------------------------- |
| **OmniDocBench Mean Latency**                | **582.9 ms** (Indra Base) / **599.9 ms** (Indra Full) / **1,127.7 ms** (Tiny)                 | 628.7 ms (PaddleOCR Tiny) / 1,030.1 ms (RapidOCR Tiny) | ⚡ Fast pure-Rust execution        |
| **Single Document Pipeline (1600×993 px)**   | **678.08 ms** (Det: 312 ms, Rec: 169 ms, 27 lines)                                            | 447.83 ms (C++ ONNX Runtime)                           | ⚡ Sub-second end-to-end           |
| **Transcription Parity (High-Res Scan)**     | **100% character-for-character identical**                                                    | Baseline reference (100%)                              | 🎯 Identical bounding boxes & text |
| **OmniDocBench Baseline Accuracy (1 - NED)** | **46.74%** (Tiny INT8) / **46.57%** (Tiny FP16) / **46.53%** (Tiny FP32) / **45.70%** (Indra) | 45.33% (PaddleOCR Tiny)                                | 🎯 Outperforms baseline (+1.4%)    |
| **Peak Memory Footprint (RAM)**              | **155.5 MB - 307.9 MB** (RTen / Pure-Rust MNN on OmniDocBench)                                | 395.8 MB (RapidOCR) / 696.2 MB (PaddleOCR)             | 🔒 **22%–78% lower memory**        |
| **CLI Binary Footprint**                     | **2.9 MB** (Self-contained `rusto` pure-Rust MNN) / 6.7 MB (`rusto-rten`)                     | ~55 MB+ (libopencv, onnxruntime shared libs)           | 📦 **95% reduction**               |
| **WASM Bundle Size**                         | **342 KB** (gzipped Pure-Rust MNN WASM)                                                       | 3.78 MB (gzipped ONNX Runtime WASM)                    | 🌐 **91% smaller web payload**     |
| **Safety & Concurrency**                     | Memory-safe (Rust borrow checker)                                                             | Manual pointers & thread locks                         | 🛡️ Data-race free concurrency      |
