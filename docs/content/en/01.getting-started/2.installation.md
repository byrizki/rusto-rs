RustO! is distributed across native package managers and registries. Model weights (`.mnn`, `.rten`) are decoupled from the SDK binaries and automatically downloaded from Hugging Face Hub (`byrizki/rusto-models`) to your local cache on first initialization (`ppocrv6-tiny` FP32 by default), or can be pre-fetched and bundled for offline environments.

## 1. Rust (`Cargo.toml`) & CLI

Add `rusto-rs` as a library dependency via `cargo`:

```bash
cargo add rusto-rs
```

Or add it directly to your `Cargo.toml`:

```toml
[dependencies]
rusto-rs = "0.4.1"
```

To install the standalone `rusto` command-line binary:

```bash
cargo install rusto-rs
rusto --version
```

### Cargo Features & Dedicated Binaries

By default, `rusto-rs` includes the pure-Rust MNN runtime (`rusto-nn`) out of the box with `default = ["ffi"]`.

RustO! provides 3 dedicated CLI binaries:

- `rusto`: Default lightweight CLI (**2.9 MB**) using pure-Rust MNN (`rusto-nn`) for `.mnn` models (including FP16 and INT8) with built-in ONNX and RTen model support.
- `rusto-rten`: Dedicated CLI (**6.7 MB**) using the native pure-Rust RTen engine (`rusto-rten`) for `.rten` models (FP32 and INT8, `--features rten`).
- `rusto-mnn`: Dedicated CLI (**5.5 MB**) using the native Alibaba MNN C++ engine (`rusto-mnn`) for `.mnn` models (`--features mnn-cpp`).

| Feature   | Default | Description                                                                               |
| :-------- | :-----: | :---------------------------------------------------------------------------------------- |
| `ffi`     | **Yes** | C FFI (`rocr_*`) and UniFFI exports for embedding `librusto` into foreign runtimes.       |
| `rten`    |   No    | Pure-Rust RTen neural network backend (`rusto-rten`) for `.rten` models.                  |
| `mnn-cpp` |   No    | Optional Alibaba MNN C++ runtime bridge (`rusto-mnn`) for hardware-accelerated execution. |
| `webgpu`  |   No    | Cross-platform GPU compute acceleration via WebGPU (`wgpu` / `rusto-nn-webgpu`).          |
| `cuda`    |   No    | NVIDIA GPU compute acceleration via `rusto-nn-cuda`.                                      |

To depend only on the core pure-Rust MNN runtime without RTen or C FFI exports:

```toml
[dependencies]
rusto-rs = { version = "0.4.0", default-features = false }
```

### HTTP Server (`rusto-server`)

Run the self-hosted Mistral-compatible `POST /v1/ocr` HTTP server from the workspace crate `crates/rusto-server`:

```bash
OCR_MODELS_DIR=/path/to/models cargo run -p rusto-server --release
```

See the [HTTP Server Guide](../02.how-to/14.use-http-server.md) for endpoint details and environment configuration.

## 2. Node.js (npm / yarn / pnpm)

Install `@rustors/node` via your preferred package manager:

```bash
npm install @rustors/node
# or yarn add @rustors/node
# or pnpm add @rustors/node
```

Pre-built native N-API binaries are automatically resolved for Linux (`x64`, `arm64`), macOS (Apple Silicon & Intel), and Windows (`x64`). Calling `RustO.initialize()` with zero arguments automatically downloads and caches `ppocrv6-tiny` on first run.

---

## 3. Python (pip / PyPI)

Install the pre-built wheel from PyPI:

```bash
pip install rusto
```

Supports Python 3.9+ across Linux, macOS, and Windows. Calling `RustO.initialize()` with zero arguments automatically downloads and caches `ppocrv6-tiny`.

---

## 4. Golang (Cgo)

Fetch the Go module:

```bash
go get github.com/byrizki/rusto-rs/packages/go
```

> **Note**: Building requires the `librusto` shared library (`librusto.so`, `librusto.dylib`, or `rusto.dll`). Set `CGO_LDFLAGS="-L/path/to/lib -Wl,-rpath,/path/to/lib"` or install `librusto` in your system library path.

## 5. Java / JVM (JitPack / Gradle / Maven)

Add `rusto-java` from JitPack using Gradle:

```groovy
repositories {
    mavenCentral()
    maven { url 'https://jitpack.io' }
}

dependencies {
    implementation 'com.github.byrizki.rusto-rs:rusto-java:0.4.1'
}
```

Or Maven:

```xml
<repositories>
    <repository>
        <id>jitpack.io</id>
        <url>https://jitpack.io</url>
    </repository>
</repositories>

<dependency>
    <groupId>com.github.byrizki.rusto-rs</groupId>
    <artifactId>rusto-java</artifactId>
    <version>0.4.1</version>
</dependency>
```

## 7. .NET / C# (NuGet)

Install the managed package from NuGet:

```bash
dotnet add package RustODotnet
```

Model weights are decoupled from the NuGet package and resolved automatically on first run via `RustO.Initialize()` or pre-downloaded using `RustO.DownloadModel("ppocrv6-tiny")`.

## 8. React Native (npm / yarn / pnpm)

Install the React Native package:

```bash
npm install @rustors/react-native
```

### iOS Setup (`ios/Podfile`)

In `ios/Podfile`, ensure static framework linkage is configured if using `use_frameworks!`:

```ruby
target 'YourApp' do
  use_frameworks! :linkage => :static
end
```

Then install CocoaPods dependencies:

```bash
cd ios && pod install
```

### Android Setup (`android/settings.gradle`)

Verify that JitPack is included in your repository list:

```groovy
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        maven { url 'https://jitpack.io' }
    }
}
```

Calling `await initialize()` automatically downloads and caches `ppocrv6-tiny` when models are not bundled inside app assets.

## 9. iOS (Swift / SPM & CocoaPods)

### Swift Package Manager (SPM)

In Xcode, select **File > Add Package Dependencies...** and enter:

```text
https://github.com/byrizki/rusto-rs.git
```

Or in your `Package.swift`:

```swift
dependencies: [
    .package(url: "https://github.com/byrizki/rusto-rs.git", from: "0.4.1")
]
```

### CocoaPods

In your project's `Podfile`:

```ruby
target 'YourApp' do
  use_frameworks!

  pod 'RustO', '~> 0.4.0'
end
```

Run `pod install`. Models can be auto-downloaded at runtime via `try RustO.initialize()`, loaded from app bundle resources via `try RustO.initializeWithBundledModels()`, or pre-fetched via `try RustO.downloadModel()`.

## 10. Android (Kotlin / Gradle)

Register JitPack in your root `settings.gradle`:

```groovy
repositories {
    google()
    mavenCentral()
    maven { url 'https://jitpack.io' }
}
```

Add `rusto-android` in your module's `build.gradle`:

```groovy
dependencies {
    implementation 'com.github.byrizki.rusto-rs:rusto-android:v0.4.1'
}
```

Calling `RustO.initialize(context)` automatically extracts bundled assets if present or downloads `ppocrv6-tiny` into `context.cacheDir/rusto/models`.

## 12. C / Native Shared Libraries & Headers

Pre-compiled dynamic shared libraries and headers are published with every [GitHub Release](https://github.com/byrizki/rusto-rs/releases):

- **Linux**: `librusto.so` (`x86_64`, `aarch64`)
- **macOS**: `librusto.dylib` (Universal `arm64` + `x86_64`)
- **Windows**: `rusto.dll`, `rusto.lib` (`x64`, `arm64`)
- **C Header**: `include/rusto.h`

To compile from source with C FFI exports enabled:

```bash
# Default release build (high-performance opt-level=3, emitted in target/release/)
cargo build --release --locked --features ffi,rten --lib

# Optional size-optimized profile (opt-level="z", emitted in target/compressed/)
cargo build --profile compressed --locked --features ffi,rten --lib
```

The compiled dynamic and static libraries are emitted in `target/release/` (or `target/compressed/` when using `--profile compressed`).
