`rusto-server` (`crates/rusto-server`) is a standalone workspace crate providing an HTTP server that implements Mistral's `POST /v1/ocr` request shape on top of `rusto-rs` (PP-OCRv6). Existing code written against Mistral's OCR HTTP API can be pointed at a self-hosted `rusto-server` instance by changing the base URL.

It is maintained as a separate workspace crate so async and web dependencies (`axum`, `tokio`, `ureq`) stay completely out of `rusto-core` and native C/mobile bindings.

> **Compatibility note**: Compatibility has been tested with plain HTTP requests shaped like Mistral's OCR API, not with Mistral's official client SDKs.

---

## Quick Start

Prepare a models directory with one subdirectory per model, each containing `det.onnx`, `rec.onnx`, and `dict.txt`:

```text
models/
├── tiny/
│   ├── det.onnx
│   ├── rec.onnx
│   └── dict.txt
└── small/
    ├── det.onnx
    ├── rec.onnx
    └── dict.txt
```

Start the server with `cargo run`:

```bash
OCR_MODELS_DIR=/path/to/models cargo run -p rusto-server --release
```

Or run a single model directory directly:

```bash
OCR_MODEL_DIR=/path/to/models/tiny cargo run -p rusto-server --release
```

By default, the server listens on `127.0.0.1:8895`.

## Endpoints

| Endpoint     | Method |   Auth   | Description                                                          |
| :----------- | :----: | :------: | :------------------------------------------------------------------- |
| `/health`    | `GET`  |    No    | Health check returning `ok`.                                         |
| `/v1/models` | `GET`  | Optional | Lists configured models and marks the `default` model.               |
| `/v1/ocr`    | `POST` | Optional | Runs OCR on a base64 `data:` URI or allowlisted `http(s)` image URL. |

When `OCR_API_KEY` is set, `/v1/*` endpoints require `Authorization: Bearer <key>` and return Mistral's error envelope on unauthorized or invalid requests.

## `POST /v1/ocr` Request & Response

### Request Fields

- **`document.type`**: `"image_url"` or `"document_url"`.
- **`document.image_url` / `document.document_url`**: Either a plain URL string or `{ "url": "..." }`. Accepts base64 `data:` URIs or `http(s)` URLs from hosts listed in `OCR_ALLOWED_HOSTS` (no redirects, 32 MB size cap). Supports **PNG** and **JPEG**.
- **`model`** _(optional)_: Selects a model per request:
  - A configured directory name (e.g. `"tiny"`, `"small"`) or `"rusto-ppocrv6-<name>"`.
  - `"mistral-ocr-*"` or omitted uses `OCR_DEFAULT_MODEL`.
  - Any other model name returns `400 Bad Request`.
  - Models are loaded lazily on first use.
- **`autorotate`** _(optional, non-Mistral extra)_: Boolean overriding `OCR_AUTOROTATE` to apply EXIF orientation before detection.

### Example Request

```bash
B64=$(base64 -w0 receipt.png)

curl -s http://127.0.0.1:8895/v1/ocr \
  -H "Content-Type: application/json" \
  -d "{
    \"model\": \"rusto-ppocrv6-tiny\",
    \"document\": {
      \"type\": \"image_url\",
      \"image_url\": \"data:image/png;base64,${B64}\"
    }
  }"
```

### Response Shape

Returns Mistral-compatible fields plus non-Mistral extras on each page (ignored by standard Mistral clients):

- `pages[]`:
  - `index`, `markdown` (recognized lines in rusto's order), `images` (always `[]`), `dimensions` (`width`, `height`, `dpi: null`).
  - **Extras**: `lines` (`text`, `score`, `box` corners), `blocks` (layout regions with `region_id`, `layout_type`, `text`, `score`, `box`), `orientation_corrected` (`bool`), and `text_angle` (length-weighted median slope in degrees, or `null`).
- `model`: `"rusto-ppocrv6-<name>"`.
- `usage_info`: `{ "pages_processed": 1, "doc_size_bytes": ... }`.

### Not Supported

PDFs, tables, headers/footers as separate output, image extraction, confidence options, annotations, `pages` selection, and the `/v1/files` upload flow are not currently supported.

## Environment Variables

| Variable            | Default          | Description                                                                                      |
| :------------------ | :--------------- | :----------------------------------------------------------------------------------------------- |
| `OCR_MODELS_DIR`    | _(unset)_        | Directory containing one subdirectory per model (`det.onnx`, `rec.onnx`, `dict.txt`).            |
| `OCR_MODEL_DIR`     | `models/tiny`    | Single-model shortcut served as `tiny` (used when `OCR_MODELS_DIR` is unset).                    |
| `OCR_DEFAULT_MODEL` | `tiny`           | Default model when `model` is omitted or uses a `mistral-ocr-*` ID.                              |
| `OCR_LISTEN`        | `127.0.0.1:8895` | TCP listen address (`host:port`).                                                                |
| `OCR_POOL_SIZE`     | `2`              | Number of `RustO` engine instances pooled per model (clamped to `1..=64`).                       |
| `OCR_API_KEY`       | _(unset)_        | Optional bearer token required on `/v1/*` routes.                                                |
| `OCR_ALLOWED_HOSTS` | _(empty)_        | Comma-separated hostnames allowed for remote `http(s)` image fetches (`data:` URIs always work). |
| `OCR_AUTOROTATE`    | `false`          | Server default for applying EXIF orientation (`1`, `true`, `yes`, `on`).                         |

## Running Tests

```bash
OCR_MODELS_DIR=/path/to/models cargo test -p rusto-server --profile release-with-debug
```

> **Note**: The workspace `release` profile uses `panic = "abort"`, which the Rust test harness cannot link against, and unoptimized inference is slow. Use `--profile release-with-debug` when running `rusto-server` integration tests.
