RustO! separates its core runtime engine from model weights so your production binaries stay under 10 MB and never bundle bloated static payload.

If you are unsure which model to pick: **start with `indraocr` (default)**. At ~16 MB, it achieves an ultra-fast **439.2 ms** mean full-document latency on OmniDocBench benchmarks with state-of-the-art accuracy on Indonesian ID cards, tax forms, receipts, as well as general Latin documents. For ultra-lightweight mobile constraints (~6 MB), choose **`ppocrv6-tiny`**.

## 1. Canonical OCR Models

RustO! provides first-class canonical models identified by name (e.g. `model = "indraocr"` or `model = "ppocrv6-tiny"`):

| Canonical Model            | Target Environment / Use Case                              |  Base Size  |  OmniDocBench Mean Latency   | Primary Strengths                                                                                                                   |
| :------------------------- | :--------------------------------------------------------- | :---------: | :--------------------------: | :---------------------------------------------------------------------------------------------------------------------------------- |
| **`indraocr`** _(Default)_ | Indonesian ID cards (KTP), SIM, receipts, regional & Latin | **~16 MB**  | **439.2 ms** (mean full-doc) | Default flagship model developed by DataLab (`datalab-to/indra-ocr`). High speed, vocabulary accuracy, and regional layout parsing. |
| **`ppocrv6-tiny`**         | Mobile apps (iOS, Android, React Native, Flutter) & CLI    | **~6.0 MB** |  1,104.4 ms (mean full-doc)  | Ultra-lightweight balance of speed, accuracy, and lightweight download size.                                                        |
| **`ppocrv6-small`**        | Desktop tools, backend services, dense scans               | **~30 MB**  |  3,700.4 ms (mean full-doc)  | Deeper backbone for better recall on small fonts, dense tables, and noise.                                                          |

| **`ppocrv3`**              | Legacy baseline compatibility                              | **~20 MB**  |     Legacy compatibility     | Backward compatibility for older PP-OCR pipelines.                                                                                  |

## 2. Decoupled Pipeline Architecture

RustO! strictly decouples the **Base OCR Pipeline** from **Optional Auxiliary Stages**:

```mermaid
flowchart TD
    subgraph BASE["Base OCR Pipeline (Pluggable Core)"]
        DET["Text Detection<br/>(det.rten)"] --> REC["Text Recognition<br/>(rec.rten + dict.txt)"]
    end

    subgraph EXTRAS["Optional Pluggable Stages (Independent Assets)"]
        UNWARP["1. Document Unwarp<br/>(uvdoc.rten)"]
        ORIENT["2. Page Orientation<br/>(orient.rten)"]
        LAYOUT["3. Layout Analysis<br/>(layout_cdla.rten / layout_publaynet.rten)"]
        CLS["4. Line Angle Classifier<br/>(cls.rten)"]
        ORDER["5. Neural Reading Order<br/>(Transformer)"]
    end

    UNWARP -.-> BASE
    ORIENT -.-> BASE
    LAYOUT -.-> BASE
    BASE -.-> CLS
    BASE -.-> ORDER
```

### Pluggable Model Assets:

- **Never bundle extras into base archives**: Base pipelines (`det.rten` + `rec.rten` + `dict.txt`) and optional stages (`cls`, `orient`, `unwarp`, `layout`, `reading-order`) are delivered as independent, pluggable `.rten` files.
- **PP-Structure v3 & Indra Layout / Reading Order Models**: Legacy layout models have been replaced with modern PP-Structure v3, Rapid Layout, and Indra OCR models:
  - **`layout_cdla.rten`** (Default): 10-class document layout segmentation (Text, Title, Figure, Figure Caption, Table, Table Caption, Header, Footer, Reference, Equation).
  - **`layout_publaynet.rten`**: 5-class document layout segmentation (Text, Title, List, Table, Figure).
  - **`order.rten` / `indra_order.rten`**: Neural reading order and layout model from DataLab Indra OCR (~2.4 MB). Functions as an integrated layout ordering transformer, sequencing multi-column text lines into natural reading order.
- **Neural Reading Order Recovery**: Transformer-based reading order sorting enabled via `--reading-order` or `enableReadingOrder`.

## 3. Model Resolution Flow

RustO! follows a deterministic 3-tier lookup flow across all bindings and the CLI:

```mermaid
flowchart LR
    A["1. User Specified Path<br/>(--model-path / modelPath / overrides)"] -->|Found| RUN["Run Inference"]
    A -->|Not Found| B["2. Local Cache Directory<br/>(~/.cache/rusto/models)"]
    B -->|Found| RUN
    B -->|Not Found| C["3. Auto-Download<br/>(GitHub Release .rten Assets)"]
    C -->|Download & Cache| RUN
```

1. **User Specified Path**: If `--model-path` / `modelPath` or explicit component paths (`--det-model`, `--rec-model`, `--dict`) are passed, RustO! checks that location first.
2. **Cache Directory**: If not found locally, RustO! looks in the cache directory (`~/.cache/rusto/models` or custom `--cache-dir`).
3. **Auto-Download**: If missing from the cache, RustO! automatically fetches the standalone `.rten` and `.txt` files directly from official GitHub Releases (`rusto-rs/models-rten`) and saves them to the cache. Offline execution is naturally achieved once files exist in the cache or local path.

## 4. Downloading Models

### Using the CLI (`rusto download`)

Download model assets ahead of time for offline or containerized deployments:

```bash
# Download default model (indraocr) to cache
rusto download

# Download a specific canonical model (e.g. ppocrv6-tiny, ppocrv6-small)
rusto download --model ppocrv6-tiny
rusto download --model ppocrv6-small

# Download a regional language pack
rusto download --model ppocrv5 --lang latin
rusto download --model ppocrv4 --lang japan

# Download all canonical models ahead of time
rusto download --all

# Specify a custom cache directory
rusto download --model indraocr --cache-dir /opt/models/cache
```

### Programmatic Download Across Bindings

All language bindings expose dedicated helper methods to trigger downloads:

#### TypeScript / Node.js

```typescript
import { RustO } from '@rustors/node';

// Download a specific model
const paths = RustO.downloadModel('indraocr', 'latin');

// Download all models ahead of time
const allPaths = RustO.downloadAllModels();
```

#### Python

```python
from rusto import RustO, download_model, download_all_models

# Download a specific pipeline
paths = download_model(model="indraocr", lang="latin")

# Download all canonical models
all_paths = download_all_models()
```

#### C# (.NET)

```csharp
using RustODotnet;

// Download a specific model
string[] paths = RustO.DownloadModel("indraocr", "latin");

// Download all models
string[] allPaths = RustO.DownloadAllModels();
```

#### Android (Kotlin)

```kotlin
import com.byrizki.rusto.RustO

// Download specific pipeline
val paths: List<String> = RustO.downloadModel(model = "indraocr")

// Download all canonical models
val allPaths: List<String> = RustO.downloadAllModels()
```

#### iOS (Swift)

```swift
import RustO

// Download specific pipeline
let paths = try RustO.downloadModel(model: "indraocr")

// Download all models
let allPaths = try RustO.downloadAllModels()
```

#### Dart / Flutter

```dart
import 'package:rusto/rusto.dart';

// Download specific pipeline
final paths = RustO.downloadModel(model: 'indraocr');

// Download all models
final allPaths = RustO.downloadAllModels();
```

## 6. Checksum Verification

Every release includes a `SHA256SUMS` file. Verify your downloaded assets:

```bash
sha256sum -c SHA256SUMS --ignore-missing
```
