RustO! separates its core runtime engine from model weights so your production binaries stay under 10 MB and never bundle bloated static payloads.

If you are unsure which model to pick: **start with `indraocr` (default)**. At ~5.5 MB (396 KB detector + 4.9 MB recognizer), it achieves an ultra-fast **439.2 ms** mean full-document latency on OmniDocBench with high accuracy on identity cards, tax forms, receipts, and general Latin documents. For ultra-compact edge constraints, choose **`ppocrv6-tiny-int8`** (~3.4 MB) or **`ppocrv6-tiny`** (~6.1 MB).

---

## 1. Canonical Base OCR Models

RustO! provides first-class canonical base models identified by name (`model = "indraocr"` or `model = "ppocrv6-tiny"`). Base models pair detection, recognition, and vocabulary metadata:

| Canonical Model            | Target Environment / Use Case                              |  Base Size   |  OmniDocBench Mean Latency   | Primary Strengths                                                                                                      |
| :------------------------- | :--------------------------------------------------------- | :----------: | :--------------------------: | :--------------------------------------------------------------------------------------------------------------------- |
| **`indraocr`** _(Default)_ | Identity cards, tax forms, receipts, regional & Latin docs | **~5.5 MB**  | **439.2 ms** (mean full-doc) | Default flagship from DataLab (`datalab-to/indra-ocr`). High speed, vocabulary precision, and regional layout parsing. |
| **`ppocrv6-tiny`**         | Mobile apps (iOS, Android, React Native, Flutter) & CLI    | **~6.1 MB**  |  1,104.4 ms (mean full-doc)  | Balanced speed, accuracy, and compact download footprint across 50+ scripts.                                           |
| **`ppocrv6-tiny-int8`**    | Resource-constrained edge, IoT, and embedded devices       | **~3.4 MB**  |       Fast INT8 mobile       | 8-bit quantized weights for minimal memory consumption with negligible accuracy drop.                                  |
| **`ppocrv6-small`**        | Desktop tools, backend services, dense scans               | **~30.5 MB** |  3,700.4 ms (mean full-doc)  | Deeper backbone for higher recall on small fonts, dense tables, and noisy scans.                                       |
| **`ppocrv6-small-int8`**   | High-throughput backend services and servers               | **~16.7 MB** |     Balanced server INT8     | 8-bit quantized small model offering desktop-grade accuracy at half the size.                                          |
| **`ppocrv6-medium-int8`**  | High-precision batch document processing clusters          |  **~77 MB**  |    High-recall batch INT8    | Maximum character recall across degraded documents and complex forms.                                                  |
| **`ppocrv5-mobile`**       | Multilingual mobile baseline (Latin, Cyrillic, Arabic)     |  **~21 MB**  | Multi-lingual baseline pack  | Proven multi-lingual baseline with optional 180° line orientation handling.                                            |
| **`ppocrv4-mobile`**       | Japanese (Kanji/Kana) & Traditional Chinese (CHT)          |  **~21 MB**  |      CJK baseline pack       | Comprehensive CJK character set support and Kannada regional compatibility.                                            |

> [!NOTE]
> Multilingual language packs and auxiliary document understanding stages are **not** bundled into the base pipeline download. They are distributed as decoupled standalone `.mnn` and `.rten` assets.

## 2. Decoupled Pipeline Architecture

RustO! decouples the **Base OCR Pipeline** from **Optional Auxiliary Stages**:

```mermaid
flowchart TD
    subgraph BASE["Base OCR Pipeline (Pluggable Core)"]
        DET["Text Detection<br/>(indra_det.mnn / det.mnn)"] --> REC["Text Recognition<br/>(indra_rec.mnn + indra_meta.json / dict.txt)"]
    end

    subgraph EXTRAS["Optional Pluggable Stages (Independent Assets)"]
        UNWARP["1. Document Unwarp<br/>(uvdoc.mnn / uvdoc.rten)"]
        ORIENT["2. Page Orientation<br/>(indra_orient.mnn / ppocr_orient.mnn)"]
        LAYOUT["3. Layout Analysis<br/>(layout_cdla.mnn / layout_publaynet.mnn)"]
        CLS["4. Line Angle Classifier<br/>(ppocr_cls.mnn / ppocr_cls.rten)"]
        ORDER["5. Neural Reading Order<br/>(indra_order.mnn / indra_order.rten)"]
    end

    UNWARP -.-> BASE
    ORIENT -.-> BASE
    LAYOUT -.-> BASE
    BASE -.-> CLS
    BASE -.-> ORDER
```

### Pluggable Model Assets:

- **Decoupled base weights**: Base pipelines (`det` + `rec` + `dict`/`meta.json`) and optional stages (`cls`, `orient`, `unwarp`, `layout`, `reading-order`) are delivered as independent `.mnn` or `.rten` files.
- **Layout & Neural Reading Order Models**:
  - **`layout_cdla.mnn` / `layout_cdla.rten`** (5.8 MB): 10-class document layout segmentation (`Text`, `Title`, `Figure`, `FigureCaption`, `Table`, `TableCaption`, `Header`, `Footer`, `Reference`, `Equation`).
  - **`layout_publaynet.mnn` / `layout_publaynet.rten`** (5.2 MB): 5-class document layout segmentation (`Text`, `Title`, `List`, `Table`, `Figure`).
  - **`indra_order.mnn` / `indra_order.rten`** (2.9 MB): DataLab Indra Neural Reading Order & Layout Transformer. Sequences multi-column text lines into natural human reading order.
- **Neural Reading Order Recovery**: Enabled via `--reading-order` on the CLI or `enableReadingOrder: true` in `InitializeConfig`.

## 3. Model Resolution Flow

RustO! follows a deterministic 3-tier lookup flow across all SDKs and the `rusto` CLI:

```mermaid
flowchart LR
    A["1. User Specified Path<br/>(--model-path / modelPath / overrides)"] -->|Found| RUN["Run Inference"]
    A -->|Not Found| B["2. Local Cache Directory<br/>(~/.cache/rusto/models)"]
    B -->|Found| RUN
    B -->|Not Found| C["3. Auto-Download<br/>(Hugging Face Hub)"]
    C -->|Download & Cache| RUN
```

1. **User Specified Path**: If `--model-path` / `modelPath` or explicit component paths (`--det-model`, `--rec-model`, `--dict`) are passed, RustO! checks that location first.
2. **Cache Directory**: If omitted, RustO! checks the cache directory (`~/.cache/rusto/models`, `RUSTO_CACHE_DIR`, or custom `--cache-dir` / `cacheDir`).
3. **Auto-Download**: If missing from the cache, RustO! downloads the standalone model and vocabulary files from Hugging Face Hub (`https://huggingface.co/byrizki/rten-models`) and atomically caches them.

## 4. Downloading Models

### Using the CLI (`rusto download`)

Download model assets ahead of time for offline or containerized deployments:

```bash
# Download default flagship model (indraocr) to cache
rusto download --model indraocr

# Download Indra OCR with auxiliary unwarp, orientation, layout, and reading-order stages
rusto download --model indraocr --orient --unwarp --layout --reading-order

# Download a specific canonical model
rusto download --model ppocrv6-tiny
rusto download --model ppocrv6-small

# Download a regional language pack
rusto download --model ppocrv5 --lang latin
rusto download --model ppocrv4 --lang japan

# Download all canonical models ahead of time
rusto download --all

# Specify a custom cache directory
rusto download --model indraocr --cache-dir /opt/models/cache
```

### Programmatic Download Across SDKs

```typescript
// TypeScript / Node.js & Web
import { RustO, downloadModel, isReady, version } from '@rustors/node';

const paths = RustO.downloadModel('indraocr', 'latin');
console.log(`RustO v${version()} ready: ${isReady()}`);
```

```python
# Python
from rusto import RustO, download_model, is_ready, version

paths = download_model(model="indraocr", lang="latin")
print(f"RustO v{version()} ready: {is_ready()}")
```

```csharp
// C# (.NET)
using RustODotnet;

string[] paths = RustO.DownloadModel("indraocr", "latin");
```

## 6. Checksum Verification

Every release includes a `SHA256SUMS` file. Verify your downloaded assets:

```bash
sha256sum -c SHA256SUMS --ignore-missing
```
