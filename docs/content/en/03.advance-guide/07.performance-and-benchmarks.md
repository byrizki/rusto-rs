All benchmarks published on this page are derived from actual, empirical measurements conducted with reproducible test suites against official baseline implementations. No speculative values or assumptions are used.

> [!NOTE]
> **Benchmark Test Environment**:
>
> - **Processor**: 11th Gen Intel(R) Core(TM) i7-1185G7 @ 3.00GHz (4 physical cores / 8 threads)
> - **Memory**: 32 GB RAM
> - **Operating System**: Linux x86_64
> - **Core Runtime**: RustO! (release profile with LTO), Pure-Rust MNN (`rusto-nn`) default runtime alongside published `rten 0.27.0` backend

## 1. OmniDocBench Comprehensive Evaluation

Evaluated against the diverse real-world **OmniDocBench** dataset (created by [DataLab](https://github.com/datalab-to), covering academic papers, textbooks, newspapers, magazines, presentation slides, and examination papers) comparing native RustO (powered by Pure-Rust MNN `rusto-nn` and `rten 0.27.0`) against official Python PaddleOCR and RapidOCR (C++ ONNX Runtime), as well as DataLab's official Indra OCR pipeline.

> [!NOTE]
> **Accuracy Parity & Memory Efficiency**: Under identical 1D spatial sorting, Indra OCR models on both Pure-Rust MNN and RTen achieve identical **45.98% accuracy (0.5402 NED)**, outperforming PaddleOCR Tiny (45.33%) and RapidOCR Tiny (44.84%). RustO with RTen uses only **177.8 MB to 200.1 MB RAM**—the lowest peak memory footprint among all evaluated OCR runtimes (less than half of RapidOCR's 392.5 MB and nearly 4x lower than PaddleOCR's 659.3 MB). Pure-Rust MNN operates at **252.8 MB to 285.5 MB RAM** with zero external C++ runtime dependencies. Upgrading from Tiny to Small quadruples model weights (6.1 MB → 29.8 MB) and inflates latency by ~3.2x with zero accuracy gain on this benchmark.

### Key Architectural Takeaways

1. **Pure-Rust MNN (`rusto-nn`, Default in v0.4.0)**:
   - Combines 100% pure Rust memory safety and zero external C++ build dependencies with optimized MNN graph and SIMD operator execution (AVX-512, AVX2+FMA, NEON, WebGPU).
   - Eliminates cold-start latency with **0.45 ms** to **1.01 ms** model loading (**8x–31x faster** than RTen and up to **38x faster** than ONNX Runtime).
   - Consistently matches or outperforms RTen and closes the gap with native C++ MNN across all document fixtures while maintaining **100% character-for-character transcription parity**.
2. **RTen (Pure Rust Backend)**:
   - Provides pure Rust execution for `.rten` model weights with the lowest observed peak RSS (**177.8 MB to 200.1 MB**).
   - Compiles down to an ultra-compact **517 KB** WebAssembly binary for zero-backend browser execution.
3. **Direct ONNX Runtime (C++ ORT)**:
   - Provides optimized CPU inference through mature multi-threaded graph optimization.
   - Requires dynamic library distribution (`libonnxruntime.so` / `.dylib` / `.dll`), creating packaging friction across containerized environments and multi-platform app targets.
4. **Alibaba MNN C++ Runtime**:
   - Fast raw CPU execution powered by assembly-level vector kernels, but requires custom C++ build scripts, linker configurations, and dynamic linking.
5. **PaddlePaddle (PaddleOCR Framework)**:
   - Official Python implementation with high GPU flexibility, but carries heavy memory overhead (up to 10.6 GB RSS during layout analysis) and a complex multi-dependency Python deployment footprint.
