RustO! provides structured upgrade paths between major releases. Review the relevant upgrade guide below for breaking changes, model format transitions, and recommended APIs.

---

## 🚀 Upgrading from v0.3 to v0.4

RustO! **v0.4.0** transitions the default inference runtime to pure-Rust MNN (`rusto-nn`) alongside RTen, keeps permissive Apache 2.0 **PP-OCRv6 Tiny FP32 (`ppocrv6-tiny`)** as the zero-config default, adds optional **DataLab Indra OCR** (`indraocr`, modified OpenRAIL-M weights), completely decouples model weights into standalone release assets hosted on Hugging Face Hub (`byrizki/rusto-models`), introduces transformer-based neural reading order recovery, and adds a pluggable multi-stage document enhancement pipeline.

### ⚡ v0.3 to v0.4 Upgrade Summary

| Aspect                    | v0.3.x                                  | v0.4.0 (Current)                                                                                            |
| :------------------------ | :-------------------------------------- | :---------------------------------------------------------------------------------------------------------- |
| **Default Model Engine**  | `ppocrv6-tiny` (~6 MB, RTen)            | **`ppocrv6-tiny`** (FP32, Apache 2.0, **46.53%** base / **62.72%** heuristic order) + opt-in **`indraocr`** |
| **Inference Runtime**     | RTen                                    | **Pure-Rust MNN (`rusto-nn`)** + RTen backend                                                               |
| **Model Distribution**    | Platform packages & bundled files       | **Decoupled standalone model files** on Hugging Face Hub                                                    |
| **Model Auto-Download**   | Manual placement or local paths         | **Deterministic 3-tier lookup & auto-download** to cache                                                    |
| **Multi-Column Reading**  | Naive horizontal scan / scrambled order | **Pure-Rust Heuristic** / **Neural Reading Order (`indra_order.rten`)**                                     |
| **Layout Detection**      | Legacy layout models                    | **PP-Structure v3 / Rapid Layout (`layout_cdla.rten`, `publaynet`)**                                        |
| **3D Document Dewarping** | None / external preprocessing required  | **Integrated UVDoc 3D unwarp network (`uvdoc.rten`)**                                                       |
| **Document Orientation**  | Fixed angle only                        | **Dynamic 4-way orientation (`indra_orient.rten` / `ppocr_orient.rten`)**                                   |
| **Model Pre-caching CLI** | Manual `curl` / `wget` scripts          | **Dedicated `rusto download` subcommand**                                                                   |

### 1. Default Model (`ppocrv6-tiny`) & Optional Indra OCR (`indraocr`)

The default canonical model resolved by `RustO::initialize()` and the CLI is permissive Apache 2.0 **`ppocrv6-tiny`** (FP32, ~5.9–6.1 MB, **46.53%** base OmniDocBench accuracy, **62.72%** with pure-Rust heuristic reading order).

- **Compact FP16 & INT8 variants**: Explicitly specify `model: "ppocrv6-tiny-fp16"` (~3.1 MB on `rusto-nn` / `rusto-webgpu`) or `"ppocrv6-tiny-int8"` (~3.3–3.4 MB) when storage is constrained.
- **Optional DataLab Indra OCR (`indraocr`)**: Available as an explicit preset (`model: "indraocr"` / `--model indraocr`, ~5.4 MB, **45.70%** base / **63.90%** full pipeline at **582.9 ms / 599.9 ms**). Note that Indra OCR weights are licensed under a modified OpenRAIL-M license (commercial API restrictions above \$20M funding/revenue).

```typescript
// v0.4 default resolves to Apache 2.0 ppocrv6-tiny FP32 with auto-caching
const ocr = RustO.initialize();

// Or explicitly request optional DataLab Indra OCR (modified OpenRAIL-M weights)
const indraOcr = RustO.initialize({ model: 'indraocr' });
```

### 2. Standalone Model Decoupling & Hugging Face Hosting

Separate platform model packages (e.g. `rusto-models-ppocrv6-tiny-*.aar`, `RustODotnet.Models.*`, `@rustors/model-*`) have been retired.

- **Zero native binary bloat**: Core library packages stay under 10 MB.
- **Auto-download on demand**: RustO! checks user paths, then `~/.cache/rusto/models`, and downloads missing model assets automatically from Hugging Face Hub (`byrizki/rusto-models`).
- **Remove old model dependencies** from `package.json`, `build.gradle`, and `.csproj`.

```diff
  // package.json
  "dependencies": {
-   "@rustors/model-ppocrv6-tiny": "^0.3.0",
    "@rustors/node": "^0.4.0"
  }
```

### 3. Neural Reading Order & Layout Transformer (`indra_order.rten`)

Multi-column documents no longer suffer from horizontal line scrambling.

- **`indra_order.rten`** (~2.9 MB) from Indra OCR functions as a layout ordering transformer, reconstructing reading flow across columns.
- Enable via `enableReadingOrder: true` in code or `--reading-order` in CLI.

```bash
rusto ocr two_column_paper.pdf --reading-order --format text-ordered
```

### 4. Optional Document Enhancement Pipeline

Auxiliary stages plug into any base OCR pipeline:

- **Geometric Dewarping (`uvdoc.rten`, ~30 MB)**: Flattens 3D curvature (thick books, folded receipts) before DBNet detection.
- **Dynamic Orientation (`orient.rten` / `indra_orient.rten`, ~6.4 MB)**: Evaluates 0°/90°/180°/270° rotation and rotates canvas upright.
- **Layout Detection (`layout_cdla.rten` / `layout_publaynet.rten`)**: 10-class or 5-class semantic segmentation.
- **Line Direction Classifier (`cls.rten`, ~585 KB)**: Flips inverted 180° lines upright.

```typescript
const ocr = RustO.initialize({
  model: 'indraocr',
  enableReadingOrder: true,
  layoutVariant: 'cdla',
  unwarp: { enabled: true },
  orientation: { enabled: true, thresh: 0.85 },
});
```

### 5. Dedicated Model Downloader CLI (`rusto download`)

Pre-cache models ahead of time for offline systems, Docker images, and CI runners:

```bash
rusto download
rusto download --model ppocrv6-tiny
rusto download --all
```

### 6. Fluent Builder Chaining API & 6-Phase Pipeline Options

In v0.4.0, text detection transitions to a clean, fluent builder chaining API ending in `.run()`, replacing monolithic options objects and disjoint `detect_layout` / `unwarp` calls:

- **Strictly `.run()`**: Every fluent chain terminates with `.run()` across all 11 platform bindings.
- **Pipelined Layout & Unwarp**: Activated directly via `.withLayoutReading()` and `.withAutoUnwarp()`.
- **6 Structured Execution Phases**: Grouped into `preDetection`, `detection`, `postDetection`, `preRecognition`, `recognition`, and `postRecognition`.
- **4 Boolean Pipeline Toggles**: `withAutoUnwarp()`, `withLayoutReading()`, `withOrientationDetection()`, and `withLineClassification()`.

#### Code Comparison (TypeScript / Node.js)

```typescript
// ❌ v0.3.x: Bloated nested options object
const results = await engine.detectTextFile(
  'invoice.png',
  JSON.stringify({
    unwarp: true,
    layout: true,
    postprocess: { useDilation: true },
  })
);

// ✅ v0.4.0: Fluent builder chaining ending in .run()
const results = engine
  .detectText('invoice.png')
  .withAutoUnwarp()
  .withLayoutReading()
  .withPostDetection({ useDilation: true })
  .asLines()
  .run();
```

#### Code Comparison (Rust)

```rust
// ❌ v0.3.x: Monolithic struct with disjoint layout calls
let options = OcrRunOptions {
    unwarp: Some(true),
    layout: Some(true),
    postprocess: Some(PostprocessRunOptions { use_dilation: Some(true), ..Default::default() }),
    ..Default::default()
};
let result = ocr.detect_text(&image, &options)?;

// ✅ v0.4.0: Fluent builder chaining with pipelined stages
let result = ocr.detect_text_builder(image)
    .with_auto_unwarp(true)
    .with_layout_reading(true)
    .with_post_detection(PostDetectionOptions { use_dilation: Some(true), ..Default::default() })
    .asLines()
    .run()?;
```

## 📦 Upgrading from v0.2 to v0.3

RustO! **v0.3.0** transitioned the inference engine to pure Rust RTen, eliminated C++/CMake toolchains, and decoupled options into `InitializeConfig` and `OcrRunOptions`.

### ⚡ v0.2 to v0.3 Summary

| Aspect                    | v0.2.x                                  | v0.3.0                                                                          |
| :------------------------ | :-------------------------------------- | :------------------------------------------------------------------------------ |
| **Core Inference Engine** | Alibaba MNN (requires C++ / CMake)      | **Pure Rust [RTen](https://github.com/robertknight/rten)** (zero C++ toolchain) |
| **Model Formats**         | Proprietary `.mnn`                      | FlatBuffers **`.rten`** or standard **`.onnx`**                                 |
| **Inference Session API** | `MnnSession`                            | **`EngineSession`** (implements `InferenceSession`)                             |
| **Configuration Model**   | Nested `preprocessing` block            | Decoupled **`InitializeConfig`** & **`OcrRunOptions`**                          |
| **NPM Package Names**     | Standalone (`react-rusto`, `rusto-web`) | Scoped **`@rustors/*`** (`@rustors/react`, `@rustors/web`)                      |

### Model Formats & Session API

Proprietary `.mnn` models were replaced with FlatBuffers `.rten` or `.onnx`. `MnnSession` was replaced by generic `EngineSession`:

```rust
use rusto::session::EngineSession;

let det_session = EngineSession::from_det_config(&config.det)?;
let rec_session = EngineSession::from_rec_config(&config.rec)?;
```

### Decoupled Configuration & Runtime Options

Options are separated into static one-time setup (`InitializeConfig`) and per-request runtime options (`OcrRunOptions`):

```rust
use rusto::{InitializeConfig, OcrRunOptions, OutputGranularity, RustO};

// Static initialization (thread-safe, load once)
let mut ocr = RustO::initialize(InitializeConfig::from_json(r#"{"model":"indraocr"}"#)?)?;

// Per-request options (stateless, concurrent)
let mut options = OcrRunOptions::default();
options.detection.box_threshold = 0.6;
options.output_granularity = OutputGranularity::Lines;

let result = ocr.detect_text(&image, &options)?;
```

### Package Namespaces Migration (`@rustors/*`)

All npm packages migrated to the official `@rustors` organization scope:

| Legacy Package (v0.2) | Official Package (v0.3+)                                                       | Notes                          |
| :-------------------- | :----------------------------------------------------------------------------- | :----------------------------- |
| `react-native-rusto`  | [`@rustors/react-native`](https://www.npmjs.com/package/@rustors/react-native) | Native JNI/TurboModule bridge  |
| `rusto-web`           | [`@rustors/web`](https://www.npmjs.com/package/@rustors/web)                   | Browser WASM RTen engine       |
| `react-rusto`         | [`@rustors/react`](https://www.npmjs.com/package/@rustors/react)               | React hooks & context provider |

### Migration Checklist

- [ ] **Step 1**: Use model weights hosted on Hugging Face Hub (`byrizki/rusto-models`).
- [ ] **Step 2**: Update dependencies to latest release (using `@rustors/*` for npm).
- [ ] **Step 3**: Remove retired native model dependencies (`rusto-models-*`, `@rustors/model-*`).
- [ ] **Step 4**: Separate static `InitializeConfig` from per-image `OcrRunOptions`.
- [ ] **Step 5**: Enable `--reading-order` or `enableReadingOrder: true` for multi-column documents.
- [ ] **Step 6**: Validate OCR output and bounding boxes on test images.
