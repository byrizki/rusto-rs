RustO! provides OCR capabilities across dozens of languages. Models are organized into **default flagship models (`indraocr`)**, **bilingual models (`ppocrv6`)**, and **specialized regional language packs (`ppocrv5` & `ppocrv4`)**.

---

## 1. Flagship & Bilingual Models

### Default Flagship: Indra OCR (Indonesian & Multilingual Vernacular)

The default **Indra OCR** pipeline (developed by DataLab, `datalab-to/indra-ocr`) is specialized for Indonesian vernacular vocabulary, regional identity documents (KTP, SIM), tax forms, and local receipts, while providing superior Latin script accuracy. It also provides dedicated script models such as CJK recognition (`indra_rec_cjk.rten`, `--lang cjk`).

### PP-OCRv6 Bilingual Scope (Chinese + English / Latin)

The **PP-OCRv6** models provide bilingual coverage for Chinese, English, and standard Latin scripts:

| Tier                            | Dictionary Size       | Script & Character Coverage                                                                                                                                               | Best For                                                                                    |
| :------------------------------ | :-------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------ |
| **Indra OCR** (Default)         | Specialized Meta JSON | Indonesian vernacular, English, Latin script, numbers, punctuation, and currency symbols (`Rp`, `$`, etc.).                                                               | Indonesian identity cards, tax forms, receipts, and high-speed Latin document OCR.          |
| **PP-OCRv6 Tiny**               | **6,904 characters**  | Simplified Chinese, English, standard Latin alphabet (Indonesian, Spanish, French, German), numerals (0-9), punctuation, and currency symbols (`$`, `€`, `¥`, `£`, `Rp`). | Mobile apps, receipts, invoices, and standard documents in English, Indonesian, or Chinese. |
| **PP-OCRv6 Small** & **Medium** | **18,708 characters** | All characters in Tiny plus Traditional Chinese ideographs, rare CJK characters, and Japanese Kana (Hiragana and Katakana).                                               | Scans containing mixed Chinese, Japanese Kana, and Latin text.                              |

> **Important**: Standard base models do not recognize Korean Hangul, Arabic, Cyrillic, Devanagari (Hindi), Thai, Greek, or South Indian scripts. For those writing systems, use the dedicated language models below.

## 3. How to Switch Language Models in Code

With RustO!'s model manager, switching languages is as simple as providing the canonical `lang` identifier. RustO! automatically resolves the corresponding recognition model and vocabulary dictionary:

### In Rust:

```rust
use rusto::{InitializeConfig, RustO};

// Initialize with universal detector + Japanese recognition model
let config = InitializeConfig::from_json(r#"{
    "model": "ppocrv4",
    "lang": "japan"
}"#)?;

let mut ocr = RustO::initialize(config)?;
let results = ocr.detect_text_file("japanese_receipt.jpg")?;
```

### In Node.js:

```typescript
import { RustO } from '@rustors/node';

const ocr = RustO.initialize({
  model: 'ppocrv5',
  lang: 'arabic',
});

const lines = ocr.detectTextFile('arabic_invoice.pdf');
```

### In Python:

```python
from rusto import RustO, create_initialize_config_for_model

config = create_initialize_config_for_model(model="ppocrv5", lang="korean")
engine = RustO.initialize(config)

lines = engine.detect_text_file("korean_document.png")
```

## 5. Right-to-Left (RTL) Scripts

When processing **Arabic, Persian, or Urdu**:

- The recognizer reads characters in their natural visual order from left to right across the cropped text slice.
- Bounding polygon vertices in structured output reflect true coordinate space on the document.
- In spatial text mode (`OutputGranularity::Spatial`), lines are formatted preserving individual word coordinates and token ordering.
